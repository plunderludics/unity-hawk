# There are two state-saving mechanisms in qemu which have different pros/cons
# One called savevm/loadvm
# - Saves *within* the current disk image file (very inconvenient, doesn't seem easy to extract/manipulate)
# - Also seems to be incompatible with disk image overlays / '-snapshot' mode, really annoying
# - Saves disk state (as a diff I think) and internal vm state (cpu + ram)
# - Save and load at runtime is instantaneous

# Another called 'migrate'
# - Saves to a standalone file, not attached to disk image like savevm
# - Only saves vm state, not disk contents
# - Seems a state file can only be loaded when the qemu process starts, can't quick-load at runtime
#  - (Except maybe with 'cpr', but haven't got that to work so far: https://www.qemu.org/docs/master/devel/migration/CPR.html)

# Save via migration (from qemu console):
# migrate "exec: cat > save.state"

# Load (add to launch command args):
# -incoming "exec: cat save.state"

# To save and load via savevm/loadvm (from qemu console):
# savevm mysavestate
# loadvm mysavestate

# Leaning towards migrate for convenient general use but savevm/loadvm seems like the only way to get fast loadstate at runtmie
